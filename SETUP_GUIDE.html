Binary Search Games: setup guide

Grade 12 · Unit 4 · Week 9 · Session 2 · Virtual (35 min) · Slides 13–24. Two live games, Higher or Lower! (warm-up) and Split Showdown (wrap-up), plus the Binary Lab to demo the search step by step.

Firebase is already set up from Session 1, and config.js is already filled in. Just do step 1: create a new repository called virtual12s2 and upload these files. Scores for Session 2 are kept separate from Session 1.

New this session
  • Higher-or-lower number game inside the warm-up (each student device picks its own secret number).
  • Tap-the-middle challenges: students run a real Binary Search with their finger; the game drops the unused half.
  • 🔥 Streak bonus for 3+ right in a row, shown on phones and on your board.
  • 3-2-1-GO countdown on every screen when you press Start.
  • Live moves feed and class accuracy bar on your board, plus a dot strip per player (green = right, red = wrong).
  • Auto-results: when every player finishes, the board switches to the podium by itself.
  • Auto-next: after each answer the next question opens by itself after 10 s (students can press Stay here).

1Put the games on GitHub Pages

  1. On github.com click New repository. Name it exactly virtual12s2, set it to Public, and create it.
  2. Click uploading an existing file. Drag in all the files from this folder (not the folder itself). Click Commit changes.
  3. Open Settings → Pages. Under Build and deployment choose Deploy from a branch, branch main, folder / (root), and click Save.
  4. Wait 1–2 minutes and refresh. The games are now at https://emanjeha.github.io/virtual12s2/
  5. If you use a different repository name, open config.js and change SITE_URL to match.

2Suggested 35-minute flow

0–5 minWarm-up game (slides 14–15). Open board.html?game=warmup, students scan and join, press Start.
5–10 minReveal the topic and mission (slide 16). Play the 3D video, or use it as homework review.
10–20 minLearn (slides 17–20). Share lab.html: press Step to trace key 8 together, then try 50 (not found) and the names list.
20–27 minWe do + You do (slides 21–23). Students trace “Sara” and “Zaid”; they can check themselves in the Lab.
27–35 minWrap-up game + exit ticket (slide 24). Press Switch to Split Showdown, Start, then Show answers for the exit tickets.

3Run it in class

Shared screenOpen https://emanjeha.github.io/virtual12s2/board.html?game=warmup and press Full screen, then share that tab in your online meeting. The QR code and join link appear on the left.
StudentsOne device each (or one per breakout pair). They scan the QR code or open the link, type their name and press Join.
StartPress Start game. Everyone sees 3-2-1-GO, then the questions. The board re-ranks live and shows each move in the Live moves feed.
EndResults open by themselves when everyone finishes. Or press End game to stop and show the podium and the hardest questions.
Wrap-upPress Switch to Split Showdown. After it ends, press Show answers to read every exit ticket.
Binary Labhttps://emanjeha.github.io/virtual12s2/lab.html. Step (or the → key) walks through one action at a time with the Python line highlighted. I’ll guess your number lets the computer find a student’s secret number by halving.
Next classPress New round (click twice). This clears the board for a fresh group.

4Good to know

  • Practice mode: without internet access to Firebase, students can still play, but nothing appears on the board.
  • Refreshing is safe: if a page reloads, the student continues where they were (even mid-number-game).
  • Late players can join at any time while the game is live.
  • Scoring: 100 points per correct answer, up to 50 for speed, and a streak bonus (+20, +40, +60) from the 3rd right answer in a row. In the warm-up, cracking the mystery topic is worth +200.
  • Keyboard: on a laptop, students can answer multiple-choice with keys 1–4 or A–D and press Enter for the next question.
  • Changing questions: edit questions.js in GitHub (pencil icon) and commit. The top of that file explains each question type.
  • Who can control the board: anyone who opens board.html can press Start or End, so don't share that link with students.

5If you ever need a new Firebase

  1. Go to console.firebase.google.com, create a project, then Build → Realtime Database → Create Database (location europe-west1), test mode.
  2. In Rules, paste {"rules":{"sessions":{".read":true,".write":true}}} and click Publish.
  3. In Project settings → Your apps → </>, register a web app and copy the values into config.js.
